# 네이버 SA 솔루션

네이버 검색광고(SA) API 기반 **광고대행사 멀티계정 관리 + 자동 리포트** 솔루션

- 대시보드: `/smart-sa` (성과 요약 · 캠페인/그룹/키워드/타겟/시간대 분석)
- 자동 리포트: 광고주별 일간/주간/월간 엑셀 리포트 이메일 발송
- 성과개선 전략: 증액(Upselling) / 감액(Downselling) / 원클릭 계정분석 제안
- **이고진 입찰관리**: `/egojin-bid` (쇼핑검색 소재 입찰가 주기 자동 조정 — 아래 별도 섹션)

---

## ⚡ 빠른 시작

### 1. 설치

```bash
npm install
cp .env.example .env
```

### 2. .env 설정

```env
PORT=3000
SITE_DOMAIN=https://yourdomain.com
SESSION_SECRET=랜덤하게_긴_문자열
DATABASE_URL=postgresql://... (Supabase 등 PostgreSQL)
CRON_SECRET=랜덤하게_긴_문자열   # Vercel 크론 보안 키
```

> 네이버 SA API 키, 광고주 계정, 발송용 SMTP는 **대시보드 웹 UI**에서 등록합니다.
> (API 설정 → 대행사 자격증명 / 광고주 관리 → 계정 연결)

### 3. 실행

```bash
npm start                 # 서버 + 스케줄러
npm run report:daily      # 리포트 즉시 테스트 (weekly/monthly 동일)
```

## 🔀 기능 플래그

`config/index.js`의 `features`에서 일원화 관리 (대시보드/스케줄러 공용):

| 플래그 | 기본값 | 설명 |
|---|---|---|
| `DA` | `false` | DA(GFA) 성과 대시보드 + DA 리포트 (공식 API 연동 전까지 OFF) |
| `AUTOBID` | `false` | 파워링크 자동입찰 (원클릭 계정분석 제안으로 대체) |
| `SHOPPING_BID` | `false` | 쇼핑검색 자동입찰 |

## 🔄 데이터 동기화

- Vercel 크론(`vercel.json`)이 매일 전 계정의 전일 성과를 DB에 저장
  - `stat_daily_detail`: AD_DETAIL + 전환 리포트 (키워드/시간대/기기 분석용)
  - `stat_campaign_daily`: Stats API 캠페인 합계 (네이버 대시보드와 일치)
- 동기화는 계정+날짜 단위 **트랜잭션 + advisory lock**으로 원자적 처리 (중복 실행 시 이중 집계 방지)
- 광고주별 대행사 자격증명(`agency_credentials`)이 연결된 경우 해당 키로 동기화

## 🎯 이고진 입찰관리 (`/egojin-bid`)

네이버 쇼핑검색 소재(nccAdId) 입찰가를 **블렌딩 ROAS 기반으로 주기 자동 조정**하는 별도 웹앱.
기존 솔루션과 같은 서버·DB·계정을 공유하지만 URL과 UI가 독립되어 있다.

### 구조 (`src/bidapp/`)
| 파일 | 역할 |
|---|---|
| `logic.js` | 순수 판정 로직 (블렌딩ROAS·핵심소재·판정·권장입찰가) — `npm run test:bid` |
| `db.js` | `bid_*` 테이블 스키마 + DAO (소재/주차성과/설정/규칙/조정/감사로그/알림/월간리포트) |
| `collector.js` | 소재 동기화 + `/stats` 소재 단위 4주 성과 수집 (간접전환 포함 convAmt/ccnt) |
| `engine.js` | 주간 계산·적용(안전장치)·일간 모니터·월간 리포트 |
| `server.js` | 화면 6종 + 광고주 초대 + 크론 엔드포인트 |

### 핵심 로직
- **블렌딩 ROAS (2구간 가변 비율)** = (N%×매출₁ + (100-N)%×매출₂₋₄) ÷ (N%×비용₁ + (100-N)%×비용₂₋₄)
  — N = `blend_recent_weight`(1주차 비중, 기본 40, 0~100 정수, 설정 슬라이더). 구 3구간(w1/w2/w3)은 N=40으로 자동 이관
- **판정**: 보정목표(목표ROAS×분류계수) 대비 ±10% 밴드 → 증액/감액/유지. 최소 데이터(4주 비용 3만원)
  미달 시 데이터부족, 감액률 0 분류는 감액금지, 1주차 순위 > 6위면 감액 보류, 핵심소재(매출 누적기여
  70%)는 감액 상한 5%. 권장가 = 10원 단위 반올림, 최저 300원
- **매출볼륨 감액 보류 (v2)**: 감액 판정이면서 최신주 매출 < 기준매출×(1-`volume_drop_threshold` 10%)이면
  `감액보류(볼륨하락)` → auto 모드여도 자동 적용 없이 승인 대기(`hold_volume`). 승인된 소재만 API 반영, 반려 시 유지.
  기준매출 = 소재별 전월(달력) 매출 ÷ 전월 일수 × 7 (100원 단위 반올림, `bid_materials.baseline_weekly_revenue`,
  매월 1일 크론 산출 + 설정에서 수동 재계산). 전월 데이터 없는 신규 소재는 null → 미적용. 증액은 볼륨 조건 없음
- **분류 9종** [계수/증액/감액]: 일반 1.0/10/10 · 집중홍보 0.8/10/5 · 신제품 0.7/10/0 · 재고소진 0.7/15/5
  · 시즌 0.8/10/5 · 슈퍼적립 0.9/10/5 · 유입확대 0.7/15/0 · 테스트 1.0/0/0 · 비주력 1.2/5/15
- 설정 화면은 성격별 탭 구성: 블렌딩·판정 / 볼륨 보호 / 입찰 한도·데이터 / 분류 규칙 / 자동화·알림 /
  소재별 설정 / API 연동. 저장은 탭 단위, 변경 이력 `bid_setting_history` 기록

### 조정 주기 (Vercel 크론 → `/egojin-bid/api/cron/tick` 매시, KST 판별 + `bid_cron_runs` 중복 방지)
- **주간**: 매주 월 06:00 — 수집→계산→모드별 자동 적용/승인요청 (설정에서 광고주별 크론 사용 ON 필요)
- **일간**: 매일 07:00 — 비용 급증(4주 일평균 200% 초과 & ROAS < 보정목표 50%) 알림만, 수동 ±3% 대응
- **월간**: 매월 1일 06:00 — ① 기준매출 산출(전월 주간환산) → ② 4주 연속 증액/감액 소재 목표ROAS 재검토 리포트, 수동 ±15%

### 안전장치
- 변경 폭 ±20% 초과 건은 auto 모드여도 무조건 승인 필요 · `감액보류(볼륨하락)` 건은 항상 승인 필요
- 적용 전 현재 입찰가 API 재조회 검증 (불일치 시 경고 기록)
- 실패 건 `failed` 상태 + 승인함에서 재시도 · 모든 변경 `bid_audit_log` 기록 (삭제 불가)

### 권한 (v2: 마스터/광고주)
- **마스터** = 기존 마케터(admin) 계정 자동 이관 + `역할=마스터`로 초대된 계정. 모든 탭 + 설정 수정 + 조정 실행 + 승인
- **광고주** = `역할=광고주`로 초대된 계정. 대시보드·주차별 데이터·승인함·히스토리 + 승인/반려.
  **설정 탭은 열람만** (입력 disabled·저장 버튼 미노출, 저장 API는 403)
- **초대** = `/egojin-bid/viewers` (마스터 전용): 이메일 + 역할 선택 → 초대 메일(만료 72시간, 다우오피스 SMTP).
  목록에서 상태(대기/만료/가입완료/비활성)·재발송·역할 변경·계정 비활성화 관리, 전부 `bid_audit_log` 기록.
  기존 `account_viewers` 구조 재사용 (`role` 컬럼 추가)
- **API 연동** = 설정 > 자동화·API 연동 탭(마스터 전용) — 기존 솔루션과 동일 모델:
  ① **마케터 API 계정 등록** (API Key·Secret Key·매니저 Customer ID, 계정당 1개 — `/smart-sa/api-settings`와 동일 저장 정책)
  ② **광고주 추가**는 광고주명 + Customer ID만 입력 → 마케터 키로 접근 확인 → 등록 →
  소재 동기화 + 4주 성과 수집 자동 실행 (초대된 마스터도 직접 등록 가능, 접근 목록에 본인 소유분 병합)

## 💡 API 호출 최적화

- 네이버 API 병렬 호출은 동시 8개로 제한 (429 방지, 초과 시 지수 백오프 재시도)
- 마스터 리포트는 계정별 in-flight 가드로 중복 job 생성 방지 (계정당 100개 한도 보호)
- 일별 통계 리포트는 4시간 메모리 캐시
